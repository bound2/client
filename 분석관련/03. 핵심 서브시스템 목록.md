## 3-1. 렌더링 시스템

**관련 경로**: `Client/SpriteLib/`, `Client/TileRenderer.h`, `Client/MTopView.h`

### 주요 클래스

| 클래스 | 역할 |
|--------|------|
| `CSprite` | 개별 스프라이트 픽셀 데이터 보유, 다양한 블리팅 변형 제공 |
| `CSpriteSurface` | 렌더링 타겟 서페이스, Lock/Unlock, BltSprite 계열 함수 |
| `CSDLGraphics` | DirectX → SDL2 호환성 래퍼 (Color변환, 비트마스크 등) |
| `TileRenderer` | 타일 최적화 렌더링 전담 |
| `MTopView` | Zone 전체 렌더링 조율 (타일 + 오브젝트 + UI) |

### 렌더링 파이프라인

```
MTopView::Draw()
  → DrawTileSurface()       타일 버퍼에 배경 렌더링 (캐싱)
  → BltSprite()             타일 버퍼 → 주 서페이스 전송
  → DrawZone()              생물/아이템/이펙트 (y좌표 정렬 후 순차 렌더링)
  → 텍스트/UI/FadeEffect    오버레이
  → SDL2 화면 출력
```

### 픽셀 포맷

| 포맷 | 용도 |
|------|------|
| RGB565 (5:6:5) | 메인 렌더링, 파일 저장 |
| RGB555 (5:5:5) | 호환성 변형 |
| RGBA4444 | 알파 채널 스프라이트 |
| RGBA32 | SDL 렌더링 캐시 |

- 색상키(Colorkey) 방식으로 투명 픽셀 처리
- RLE 압축 스프라이트 지원 (투명 픽셀 스킵 최적화)
- y좌표 정렬 기반 Depth 처리 (`CREATURE_OUTPUT_MAP`)
- 타일 버퍼 캐싱으로 불필요한 재렌더링 방지

### SDL2 연동

- `SpriteLibBackendSDL.h` — C 인터페이스(`spritectl_*`)로 SDL2 추상화
- `SDL_Surface*` 픽셀 접근 + `SDL_Texture*` 렌더링 분리 구조
- Lock/Unlock 중첩 카운터로 안전한 픽셀 접근 보장

## 3-2. 입력 / 사운드 시스템

**관련 경로**: `Client/DXLib/`, `basic/InputCodes.h`

### 주요 클래스

| 클래스 | 역할 |
|--------|------|
| `CSDLInput` | SDL2 기반 키보드/마우스 입력 처리 |
| `CSDLAudio` | SDL_mixer 기반 효과음 재생 |
| `CSDLStream` | WAV 파일 스트리밍 재생 |
| `CSDLMusic` | SDL_mixer 기반 배경음악 재생 |

### 입력 처리 흐름

```
게임 루프 → UpdateInput()
  → SDL_PollEvent()
      SDL_KEYDOWN/UP        → m_key[256] 상태 갱신
      SDL_MOUSEMOTION       → 마우스 좌표 갱신
      SDL_MOUSEBUTTONDOWN/UP → 버튼 상태 갱신
      SDL_TEXTINPUT         → InputFocusManager (한글 IME 포함)
```

- DirectInput DIK 코드 ↔ SDL 스캔코드 매핑 테이블 (`init_key_mapping()`)
- 마우스/키보드 이벤트 콜백 함수 포인터 등록 방식

### 사운드/음악 재생

- **효과음**: `Mix_LoadWAV()` → `Mix_PlayChannel()`, 32채널 동시 재생
- **배경음악**: `Mix_PlayMusic()`, OGG/MP3/MIDI 지원
- **스트리밍**: 버퍼 리필 방식, `Update()`를 매 루프 호출 필요
- 팬/음량/주파수 제어 API 제공 (일부 SDL_mixer 미지원 항목은 스텁)

### 지원 포맷 / 제약

| 항목 | 상태 |
|------|------|
| WAV / OGG / MP3 | 지원 |
| 주파수 실시간 변경 | 미지원 (스텁) |
| IME 입력 | `InputFocusManager` 통해 지원 |

## 3-3. 네트워크 / 패킷 시스템

**관련 경로**: `Client/Packet/`, `Cpackets/`, `Gpackets/`, `Lpackets/`

### 주요 클래스

| 클래스 | 역할 |
|--------|------|
| `Packet` | 모든 패킷의 기본 인터페이스 |
| `PacketFactoryManager` | 패킷 ID → 객체 생성 팩토리 매니저 |
| `Socket` | TCP 클라이언트 소켓 (SocketImpl 패턴) |
| `Encrypter` | XOR 기반 패킷 암호화/복호화 |
| `ClientCommunicationManager` | UDP 데이터그램 통신 관리 |

### 패킷 분류

| 접두사 | 방향 | 예시 |
|--------|------|------|
| `CG*` | 클라이언트 → 게임서버 | CGMove, CGAttack, CGSay |
| `GC*` | 게임서버 → 클라이언트 | GCMove, GCAddMonster, GCSkill |
| `LC*` / `CL*` | 로그인서버 ↔ 클라이언트 | LCLoginOK, CLLogin |
| `CR*` / `RC*` | 리소스서버 통신 | RCCharacterInfo |

총 패킷 수: 약 500+

### 패킷 구조

```
[PacketID(2)] [PacketSize(4)] [Sequence(1)] [Body(가변)]
              총 헤더: 7 bytes
```

### 팩토리 패턴

```
PacketFactoryManager
  → PacketFactory (패킷 ID별 등록)
      → createPacket()   인스턴스 생성
      → read()           스트림에서 역직렬화
      → execute()        핸들러 실행
      → write()          스트림에 직렬화
```

### 암호화

- **XOR 대칭 암호화** — 타입별(uchar/uint/long 등) 독립 키 사용
- `PACKET_CG_ENCODE_KEY`로 세션 키 협상
- `SocketEncryptInputStream/OutputStream`으로 스트림 레벨 적용

## 3-4. 게임 오브젝트 시스템

**관련 경로**: `Client/MObject.h`, `MCreature.h`, `MPlayer.h`, `MNPC.h`, `MItem.h`, `MZone.h`

### 클래스 계층 구조

```
MObject
├── MCreature  (MObject + MStatus)
│   └── MCreatureWear
│       ├── MPlayer   (+ MRequestMode)
│       └── MNPC
├── MItem      (MObject + CAnimationFrame)
├── MImageObject
│   └── MAnimationObject
│       └── MInteractionObject
└── MEffect
```

### MZone - 맵 / 섹터 관리

- `MSector**` 2D 배열로 모든 타일 정보 관리
- 오브젝트별 Map (`CREATURE_MAP`, `ITEM_MAP`, `EFFECT_MAP` 등)
- 이동 제약: 지상 / 지하 / 공중 블록 구분
- `KeepObjectInSight()`: 시야 범위 초과 오브젝트 자동 제거

### MPlayer 특화 기능

- **A\* 길찾기**: `DNode` + 우선순위 큐 기반 경로 계산
- **추적 시스템**: `m_fTrace` 플래그로 크리처/아이템/섹터 추적
- **시야 관리**: 일반시야 / 조명시야 / 아이템시야 분리
- **아이템 버퍼**: 20+ 가지 상태 처리 (줍기, 사용, 거래 등)
- **공격 모드**: PEACE / NORMAL / AGGRESS / GUILD

### 아이템 시스템

- 종족별 슬롯 분리 (Slayer 14슬롯 / Vampire 11슬롯 / Ousters 12슬롯)
- 아이템 속성: 내구도, 개수, 옵션 리스트, 색상 세트
- 판정 함수: `IsGearItem()`, `IsPileItem()`, `IsGunItem()` 등

## 3-5. 이펙트 시스템

**관련 경로**: `Client/MEffect.h`, `MEffectManager.h`, `MEffectGenerator.h`

### 클래스 계층

```
MObject
└── MEffect  (+ CAnimationFrame)
    ├── MMovingEffect
    │   └── MAttachEffect
    └── MSelectableEffect
```

### 생성기(Generator) 패턴

```
MEffectGeneratorTable
  → EFFECTGENERATOR_INFO  (좌표, 방향, 지속시간, 위력 등)
  → MEffectGenerator::Generate()
      → 구체적 Generator (44종)
          → MEffect 인스턴스 생성 → Zone에 등록
```

### 이펙트 종류 (44종)

| 분류 | 예시 |
|------|------|
| 추적/공격 | ATTACK_CREATURE, ATTACK_CREATURE_HOMING, ATTACK_CREATURE_PARABOLA |
| 영역 | ATTACK_ZONE, ATTACK_ZONE_BOMB, ATTACK_ZONE_RECT |
| 정지/지속 | STOP_ZONE_CROSS, STOP_ZONE_RECT, STOP_ZONE_RHOMBUS, STOP_ZONE_WALL |
| 부착/궤도 | ATTACH_CREATURE, ATTACH_CREATURE_ORBIT, ATTACH_ZONE |
| 특수 | FALLING, RISING, RIPPLE_ZONE, METEOR_DROP, BLOODY_WALL |

### 생명주기

```
생성  →  SetFrameID / SetPosition / SetCount(지속시간)
활성  →  Update() 매 프레임 호출
종료  →  IsEnd() (g_CurrentFrame >= m_EndFrame)
정리  →  MEffectManager::Release()
```

- 이펙트 간 체인 연결 지원 (`SetLink` → 순차 실행)
- `m_bMulti`: 중복 생성 허용 여부
- 전역 프레임 카운터(`g_CurrentFrame`) 기반 타이머 통합 관리

## 3-7. 텍스트 / 한글 처리

**관련 경로**: `Client/TextSystem/`, `VS_UI/hangul/`

### 텍스트 렌더링 파이프라인

```
[Legacy 레이어] FL2.h
  g_Print() / g_PrintColorStr() / g_PrintColorStrShadow()
  → HFONT / DBCS 기반 GDI 방식 (구형)

[Modern 레이어] TextService / TextBackendSDL
  TextService::Render()
  → TextBackendSDL (SDL2 + freetype2)
  → UTF-8 정규화 → WrapText() → 글리프 렌더링
```

### 한글 IME 처리

| 클래스 | 역할 |
|--------|------|
| `CI` | 문자 입력기 기본 클래스 (조합 상태 관리) |
| `CI_KOREAN` | WM_IME_* 메시지 처리, 자모 조합 |
| `CI_CHINESE` | 중문 IME (동일 인터페이스) |

- `m_composing_char[2]`: 현재 조합 중인 문자
- `m_bl_ime_running`: IME 활성화 상태
- `ImmNotifyIME()`로 조합 취소 처리
- SDL2 환경: `SDL_TEXTINPUT` / `SDL_TEXTEDITING` 이벤트로 대체 처리

### 인코딩

- CP949 / EUC-KR → UTF-8 변환: `TextService::NormalizeText()`
- DBCS 바이트 경계 안전 처리: `g_PossibleStringCut()`
- 문자열 길이 제한 유틸: `ReduceString()` 계열

## 3-8. 압축 / 파일 관리

**관련 경로**: `Client/PackFileManager.h`, `Client/zlib.h`, `Client/huffman.h`

### 압축 라이브러리

| 라이브러리 | 용도 |
|-----------|------|
| zlib (DEFLATE) | 게임 데이터 일반 압축 |
| Huffman | 네트워크 패킷 데이터 압축 |
| RLE | 스프라이트 픽셀 데이터 압축 (SpriteLib) |

### 팩 파일 구조

```
DataFile  : [Data0] [Data1] ... [DataN]
IndexFile : [ID + FilePosition] * N
```

- `PackFileManager` (템플릿 클래스)
- ID 기반 / 파일명 기반 이중 인덱스 (`std::map`)
- `GetInputFileStream(id)`: 팩 내부 스트림 직접 접근 (seekg)

### 파일 로딩 흐름

```
LoadFromFileInfo()       인덱스 파일 파싱 (WORD: 파일 개수)
  → PackFileInfo 목록 구성
  → HasInfo(id) / GetInfo(id)  메타데이터 조회
  → GetInputFileStream(id)     팩 내 바이너리 데이터 스트림 반환
```

- `AddFile()` / `RemoveInfo()` — 런타임 팩 수정 가능
- 패치 병합 지원 (`AppendPatch` 방식, 일부 주석 처리됨)
- 바이너리 형식(`ios::binary`), 플랫폼 독립 설계
