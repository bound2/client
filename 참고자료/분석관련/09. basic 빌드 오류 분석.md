# 9. basic 프로젝트 빌드 오류 분석

---

## 오류 요약

| 종류 | 파일 | 내용 |
|------|------|------|
| **fatal error C1083** | `basic/Platform.h(192)` | `'pthread.h': No such file or directory` |
| warning C4819 | `Directory.h`, `Platform.h` | 코드 페이지(949) 표시 불가 문자 (UTF-8 BOM 없음) |

빌드 결과: **실패** (fatal error로 모든 .cpp 컴파일 중단)

---

## 근본 원인

### 오류 1 (치명적) — pthread.h 미가드

`basic/Platform.h` 라인 189~197:

```c
/* CRITICAL_SECTION for thread synchronization */
#ifndef _CRITICAL_SECTION_DEFINED
#define _CRITICAL_SECTION_DEFINED
#include <pthread.h>          ← ★ 문제 지점 (라인 192)

typedef struct _CRITICAL_SECTION {
    pthread_mutex_t mutex;
    int initialized;
} CRITICAL_SECTION, ...
```

**문제**: `#include <pthread.h>` 가 `#ifndef PLATFORM_WINDOWS` 가드 없이 작성되어 있음.

- `PLATFORM_WINDOWS` 는 `_WIN32` 감지 시 라인 37에서 정의됨 → VS2019 빌드에서 정상 정의됨
- 그러나 CRITICAL_SECTION 블록(라인 189)은 `PLATFORM_WINDOWS` 체크 없이 진입
- Windows에서 `_CRITICAL_SECTION_DEFINED` 는 `<windows.h>` 가 포함되기 전이므로 미정의 상태
- 결과: Windows에서도 `pthread.h` 를 찾으려 시도 → Windows SDK에 존재하지 않음 → **fatal error**

비교: 같은 파일의 다른 섹션들은 제대로 가드되어 있음:
```c
#ifndef PLATFORM_WINDOWS          ← 올바른 패턴
struct IDirectSoundBuffer;
...
#endif
```

### 오류 2 (경고) — 파일 인코딩

`Platform.h`, `Directory.h` 가 UTF-8(BOM 없음)으로 저장되어 있고 내부에 한국어/특수문자 포함.
MSVC는 기본 코드 페이지(CP949)로 파일을 읽으므로 C4819 경고 발생.
→ 빌드는 되나 데이터 손실 가능성 경고.

## 해결 방법

### 방법 A — vcpkg로 Windows용 pthread 설치 (코드 수정 없음, 권장)

```powershell
"C:/Users/USER/Desktop/sourceTree_root/vcpkg download/vcpkg/vcpkg.exe" install pthreads:x64-windows
```

설치 후 cmake 재구성:

```powershell
cd "C:\Users\USER\Desktop\Github_clone\dk_client"
cmake -S . -B build/vs2019 -G "Visual Studio 16 2019" -A x64 "-DCMAKE_TOOLCHAIN_FILE=C:/Users/USER/Desktop/sourceTree_root/vcpkg download/vcpkg/scripts/buildsystems/vcpkg.cmake"
```

vcpkg의 pthreads 패키지는 Windows용 pthread 호환 헤더/라이브러리를 제공하므로
`pthread.h` include 가 통과되고 `pthread_mutex_t` 타입도 사용 가능해짐.

---

### 방법 B — Platform.h 코드 수정 (근본 해결)

`basic/Platform.h` 의 CRITICAL_SECTION 블록을 `#ifndef PLATFORM_WINDOWS` 로 감싸야 함:

```c
// 현재 (문제 있는 코드)
#ifndef _CRITICAL_SECTION_DEFINED
#define _CRITICAL_SECTION_DEFINED
#include <pthread.h>
typedef struct _CRITICAL_SECTION { ... } CRITICAL_SECTION;
...
#endif

// 수정 후 (올바른 코드)
#ifndef PLATFORM_WINDOWS
#ifndef _CRITICAL_SECTION_DEFINED
#define _CRITICAL_SECTION_DEFINED
#include <pthread.h>
typedef struct _CRITICAL_SECTION { ... } CRITICAL_SECTION;
...
#endif
#endif
```

Windows에서는 `<windows.h>` 가 이미 `CRITICAL_SECTION` 을 제공하므로 pthread 구현이 불필요.

---

### 방법 C — CMake에서 MSVC 강제 include 경로 추가

pthread 헤더만 별도로 구해 include 경로에 추가하는 방법.
방법 A(vcpkg)와 실질적으로 동일하므로 A 사용 권장.

---

## 권장 순서

```
1단계: vcpkg로 pthreads 설치 (방법 A)
        → 코드 수정 없이 즉시 빌드 가능 여부 확인

2단계: 빌드 성공 확인 후
        → Platform.h 코드 가드 수정 (방법 B) 으로 근본 원인 제거
        → 방법 A는 불필요한 의존성이 되므로 제거 가능
```

## C4819 경고 해결 (선택)

경고이므로 빌드 자체는 가능하지만 억제하려면:

**방법 1**: CMakeLists.txt 에 MSVC 컴파일 옵션 추가
```cmake
if(MSVC)
    add_compile_options(/utf-8)
endif()
```
`/utf-8` 옵션은 소스 파일을 UTF-8로 강제 해석.

**방법 2**: 해당 파일들을 UTF-8 with BOM 으로 재저장 (VS2019에서 파일 > 다른 이름으로 저장 > 인코딩 선택)
