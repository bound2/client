# 커밋 로그

- 일시: 2026-08-18
- 대상: `Client/MinTr.h`
- 유형: fix (빌드 오류 수정, VS_UI - MinTr.h 구문 오류)

## 원인

`_MinTraceErrA`, `_MinTraceErrW`, `_MinTraceWarA`, `_MinTraceWarW` 네 함수 모두
`#ifdef PLATFORM_WINDOWS` 분기에서, 내부 `if (hWnd) { ... }` 블록은 닫으면서 정작
바깥쪽 함수 본문 자체의 닫는 `}`를 빠뜨리고 바로 `#else`로 넘어가고 있었음:

```cpp
#ifdef PLATFORM_WINDOWS
inline void _MinTraceErrA(LPCSTR p)
{
    ...
    if (hWnd)
    {
        ...
    }
    // <- 함수를 닫는 '}' 누락
#else
inline void _MinTraceErrA(LPCSTR p) { ... }
#endif
```

Windows 빌드에서는 `#else` 분기가 전처리 단계에서 통째로 제거되므로, 다음에 오는
`_MinTraceErrW` 등의 함수 선언이 앞 함수의 아직 열려 있는 본문 안에 중첩된 것처럼
파싱됨. C++는 지역(중첩) 함수 정의를 허용하지 않으므로 `error C2601`(지역 함수 정의
오류), 이어서 중첩이 깊어지며 `fatal error C1075`(짝이 맞는 `{`를 찾을 수 없음)까지
발생해 `VS_UI.vcxproj`를 포함해 `MinTr.h`를 include하는 모든 파일의 컴파일이
중단되고 있었음.

## 커밋 메시지

```
fix: MinTr.h에서 4개 함수의 닫는 중괄호 누락 수정

_MinTraceErrA/_MinTraceErrW/_MinTraceWarA/_MinTraceWarW의
PLATFORM_WINDOWS 분기에서 함수 본문을 닫는 '}'가 빠져 있어, 다음
함수 선언이 이전 함수 내부에 중첩된 것처럼 파싱되며 C2601/C1075
오류가 연쇄적으로 발생하던 문제 수정. 각 함수에 누락된 '}'를
추가하고, 함께 있던 불필요한 줄 끝 공백도 정리함(로직 변경 없음).
```
