처음으로 컴파일됨)에 798건의 컴파일 오류가 있었음. 오류를 파일별로 묶어보니
CSystemInfo.cpp(80)/MWorkThread.cpp(58)/BloodBibleSignInfo.h(56)/
CAvi.cpp(44)/GameInit.cpp(40)/MMusic.cpp(36)/GameUI.cpp(30)/

쪽에도 있는지 사용자와 상의해 깊이 조사하기로 함.

## 조사 결과

### 1. `ServerInformation` - Windows SDK `combaseapi.h`와 이름 충돌

`class ServerInformation`(`Client/ServerInformation.h`)이 Windows SDK
`combaseapi.h`의 `typedef struct tagServerInformation {...} ServerInformation,
*PServerInformation;`과 같은 이름으로 전역 네임스페이스에서 충돌
(`error C2371: 'ServerInformation': 재정의`). 헝가리언 표기 규칙에 맞춰
`CServerInformation`으로 리네임(`ServerInformation.h/.cpp`,
`GameInit.cpp`, `GameUI.cpp`, `CWaitUIUpdate.cpp`, `SizeOfObjects.cpp`,
`Packet/Lpackets/LCWorldListHandler.cpp` - 총 7개 파일, 정확히 클래스명
토큰만 치환, CRLF/인코딩은 그대로 보존).

### 2. `CAvi.cpp` - 죽은 코드 (아무도 호출 안 함)

레거시 MCI/AVI 인트로 동영상 재생 클래스. 유일한 호출부 2곳
(`GlobalVariables.cpp`, `MissingGlobals.cpp`)이 이미 다른 이유로 CMake에서
제외되어 있어, `CAvi` 클래스 자체가 아무 데서도 인스턴스화되지 않는 걸 확인.
`CMakeLists.txt`에서 `CLIENT_MAIN_SOURCES`에서 제외.

### 3. 사운드 헤더 중복 - `Client/soundbuf.cpp`/`mp3.cpp`(루트) vs `Client/DXLib/`

VC6 원본(`client-master_vs6/Client/DXLib/DXLib.dsp`)을 확인한 결과,
`soundbuf.cpp`/`mp3.cpp`/`CDirectSound.cpp`/`CDirectSoundStream.cpp`는
**원래부터 `DXLib.lib`에만 속했고 `Client.dsp`(EXE)에는 없었음**. 현재
`Client/DXLib/`에 이미 SDL로 마이그레이션된 버전이 있는데, `CMakeLists.txt`의
`file(GLOB CLIENT_MAIN_SOURCES Client/*.cpp ...)`가 `Client/` 루트에 남아있던
(아직 real `<dsound.h>`를 쓰는) 구버전 복사본까지 함께 주워서 `DarkEden.exe`에
직접 컴파일해 넣고 있었음 - 컴파일 오류(real DSound.h 충돌)와 잠재적
LNK2005 중복 심볼 위험 둘 다의 원인. `CMakeLists.txt`에서
`Client/soundbuf.cpp`/`Client/mp3.cpp`(루트)만 정확히 제외(`DXLib/` 하위는
글롭 대상이 아니라 원래 영향 없음).

### 4. `basic/AudioTypes.h` vs 실제 `<mmsystem.h>`/`<mmiscapi.h>`/`<dsound.h>`

`AudioTypes.h`가 SDL 대체용으로 `HMMIO`/`MMCKINFO`/`DSBPOSITIONNOTIFY`를
무조건 정의하는데, 이 프로젝트 안에 아직 남아있던 real 헤더 include들
(`GameInit.cpp`/`GameInitInfo.cpp`/`GameMain.cpp`/`CGameUpdate.cpp`/
`CWaitUIUpdate.cpp`/`WavePackFileManager.cpp`의 `<MMSystem.h>`,
`MZoneSoundManager.h`의 `<DSound.h>`)와 같은 번역 단위에서 만나면
재정의 오류가 남. `AudioTypes.h`가 real 헤더의 include guard
(`_INC_MMSYSTEM`/`_MMISCAPI_H_`/`__DSOUND_INCLUDED__`)를 감지해서 그럴 때는
자신의 정의를 건너뛰도록 가드 추가.

### 5. `MZoneSoundManager.h` - real `<DSound.h>` 제거

`Client/CSoundPartManager.h`에서 이미 확립된 패턴(2026-08-19,
`2d12c9e`/`e78036f`)과 동일하게, real `<DSound.h>` include를 제거하고
`LPDIRECTSOUNDBUFFER`를 opaque 포인터로 직접 전방 선언.

### 6. `IDirectSoundBuffer` 불완전 타입 - 직접 COM 메서드 호출 잔존

`LPDIRECTSOUNDBUFFER`를 전방 선언(불완전 타입)만 해둔 상태에서
`m_pBuffer->Stop()`/`->Release()`/`->Play()`처럼 COM 인터페이스 메서드를 직접
호출하는 코드가 `MZoneSoundManager.cpp`(4곳)와 `CSoundPartManager.cpp`(3곳),
그리고 `ClientFunction.cpp`/`GameInit.cpp`/`GameMain.cpp`(각 1~3곳, "old
buffer 교체 시 Release" 패턴)에 남아있어 `error C2027` 발생. 이미 SDL 백엔드로
이 역할을 대신하는 `CSDLAudio`(`g_SDLAudio`, `Client/DXLib/CDirectSound.h`)가
`Stop(LPDIRECTSOUNDBUFFER)`/`Release(LPDIRECTSOUNDBUFFER)`/
`Play(LPDIRECTSOUNDBUFFER, bool)`를 이미 제공하고 있어서, 직접 호출을 전부
`g_SDLAudio.Stop(...)`/`g_SDLAudio.Release(...)`/`g_SDLAudio.Play(...)` 호출로
교체(`#ifdef PLATFORM_WINDOWS`로 감싸져 있던 곳은 그 분기 자체를 제거하고
모든 플랫폼에서 동일하게 동작하도록 통일).

### 7. `CMP3`/`MMusic` - real MCI/MIDI API가 `basic/Platform.h`의 설계와 충돌

`CMP3.cpp`/`MMusic.cpp`는 진짜 Win32 MCI/MIDI 함수(`mciSendCommand`,
`midiOutOpen` 등)를 직접 호출하는데, `basic/Platform.h`가 이미
"real `<MMSystem.h>`는 어디서도 include하지 않는다"는 원칙으로
`timeGetTime()`/`GetTickCount()`를 매크로로 치환해두고 있어서, real
`<MMSystem.h>`를 include하면 그 매크로와 충돌해 새 오류가 남(원 구현을 되살릴
수 없는 구조적 문제 - 자세한 내용은 `참고자료/작업필요stub.md` 2-1항 참고).
`CMP3`는 호출부가 `__USE_MP3__`(영구 비활성화)로 이미 죽어있어 안전하게
스텁으로 전환, `MMusic`은 여전히 런타임에 도달 가능한 폴백 경로라 새 플래그
`__USE_REAL_MIDI__`(영구 미정의)를 도입해 같은 방식으로 스텁 전환하고 스텁임을
명시적으로 기록함.
